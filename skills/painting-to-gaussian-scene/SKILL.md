# 油画 → 高斯笔触沉浸场景（制作 Skill）

本 Skill 记录了《罂粟花田》和《阿让特伊的帆船赛》两幅画从原画到 360° 沉浸场景的完整做法，包括已经验证过的参数、踩过的坑和验收标准。接手的人按本文操作，可以新增一幅画，或继续打磨现有场景。

> 项目根目录：`monet-immersive/`（下文路径都相对于它）。先读 `HANDOFF.md` 了解项目背景，再读本文。

---

## 0. 用户的审美要求（最高优先级，每一步都要对照）

用户（皓宇）反复强调过的要求如下，违反任何一条都算不合格：

1. **明亮、通透、偏冷**。不能暗，也不能偏土黄或橄榄色。莫奈的画是户外的阳光。
2. **精致、清晰**。笔触边缘要利落，不能“糊糊的”。
3. **干净**。不能有“脏脏的”斑驳纹理，比如随机亮暗噪点、灰色碎笔、深色杂点。
4. **一体**。看不出原画的矩形画框边界，画内和画外扩展要连成一个整体。
5. **构图忠于原画**。从观看点看过去，画面与原画逐像素一致；转场起止两端与 DOM 里的原画完全对齐。
6. 视觉优先于交互。交互可以简单，画面必须好看。

## 2. 第 ① 步：选画与资产

- **选画标准**：
  - 有明确的地平线或水平线，便于推算深度。
  - 前、中、远景层次清楚。
  - 大面积天空、水或草地可以自然向四周延展。
  - 风景类优先，室内和肖像不适合。
- **来源**：Wikimedia Commons 的公有领域高清图。下载后缩到长边约 2048px，JPEG 质量 90 左右，放进 `assets/paintings/<id>.jpg`。
- 记录画作信息（中法文标题、年代、尺寸、馆藏、简介），写进 `scenes.js` 的 `info`。
- 新增中文文案后，**必须**重新生成字体子集，否则新字会显示成方框：`python3 tools/fonts.py`。
- 画作必须同源加载，或者带 CORS 头加载。`loadImage` 已经设置了 `crossOrigin='anonymous'`，否则 `getImageData` 会报 canvas tainted。

## 3. 第 ② 步：相机模型、语义分类与深度（`src/scenes.js`）

### 3.1 相机 `cam`

| 字段 | 含义 | 经验值 |
|---|---|---|
| `f` | 焦距，画面宽度归一化为 1。0.866 对应约 60° 水平视场 | 0.866 |
| `h` | 眼睛离地/离水面的高度（m） | 草地 2.4，水面 1.6 |
| `vH` | 地平线在画面中的纵坐标 v（0 为顶部，1 为底部） | **必须对着原画量**，罂粟 0.505，帆船 0.55 |
| `maxD` | 地面最远深度（m） | 60–95 |
| `dolly` | 进入画境后相机前推的距离 | 1.4–1.8 |
| `sky` | 天空笔触的深度（m） | 500–650 |

视线公式（全项目的根基）：

```
dir(u, v) = (u - 0.5,  -(v - vH) * asp,  -f)      asp = 图高 / 图宽
world     = dir * depth / f
```

地面深度：`groundDepth = h*f / ((v - vH)*asp)`，地平线以上返回 `maxD`。

### 3.2 `classify(u, v, r, g, b, rand)` 规则

逐像素调用（输入是 b1 轻模糊后的颜色），返回 `{cls, depth, hot, flex}`：

- `cls` 的取值见下表。着色器按类别做动效，不要随意新增编号。如果确实要新增，需要同步修改 `splats.js` 中的所有分支。

| 编号 | 类别 | 用途 / 动效 |
|---|---|---|
| 0 SKY | 天空 | 极慢漂移，柔边 |
| 1 GRASS | 草 | 风吹，草浪 |
| 2 FLOWER | 花 | 风吹，饱和 |
| 3 TREE | 树冠 | 随高度增加摇摆幅度（flex） |
| 4 STATIC | 房屋、岸、桅杆等 | 不动 |
| 5 FIGURE | 人物 | 衣摆轻动 |
| 6 WATER | 水 | 水平波光，掠射压扁 |
| 7 SAIL | 帆 | 鼓风（flex 从底到顶 0→1） |
| 8 PETAL | 飘落花瓣 | 粒子 |
| 9 MOTE | 光尘 | 粒子，尺寸有上限 |
| 10 HALO | 热点光晕 | 呼吸发光 |
| 11 GLINT | 水面高光 | 闪烁 |

- **判断顺序**：从具体到一般。人物、帆这类具体多边形放最前，然后是水或地面线，接着是岸、树，最后兜底为 SKY。
- **区域描述**：用 `polyline`（分段直线，例如水岸线、树顶线）、`inPoly`、`inEllipse`、`inRect` 手工勾画。坐标对着原画量（可以用图片编辑器读取像素坐标再除以宽高）。
- **颜色二次判断**：在多边形内部，还要用颜色排除“其实是天空的像素”，例如 `b >= r && L > 0.55` 的像素判为天空。否则树冠边缘会混入天空笔触，变得脏。
- **深度原则**：
  - 地面、水面用 `groundDepth(v)`。
  - 竖立的物体（人、帆、树、房）用它**底部触地点**的地面深度，整片物体使用同一个深度。否则物体会“躺倒”。
  - 远景物体之间深度要拉开（例如帆 30/33/37/44 m），这样转身时有视差，但不能超过地面深度的合理范围。
- **hot**：热点 id（1..n），对应 `hotspots` 数组。热点区域内的笔触会复制出光晕，参与聚焦。
- **flex**：受风系数，0 到 1。树按离地高度增大；帆从底到顶为 0→1；房屋为 0。

### 3.3 其他配置

- `grade`：调色，见第 8 步。
- `wind: {dir:[x,z], base}`：风向与基础风力。
- `hotspots`：`{id, cn, en, zoom, text}`。`zoom` 控制点击后拉近的倍数（1.35–2.6）。文案要讲画法，而不只是讲内容。
- `ext`：全景扩展布局，见第 5 步。角度单位为度，正值表示向左。

## 4. 第 ③ 步：画内笔触（`generator.js` 的 “painted strokes”）

### 4.1 预处理

- 缩到 `Q.analysisW`（640/760）。三级模糊：`b1` 半径 1、`b2` 半径 3、`b3` 半径 6。
- Sobel 梯度，加上结构张量（半径 4 模糊）。用相干度 `coh` 决定笔触是否沿结构方向。

### 4.2 分层笔触（4 层 + 特写细层）

六边形网格加 ±0.45 格抖动：

| 层 li | 网格间距 | 取色来源 | 作用 |
|---|---|---|---|
| 0 粗 | `Q.layers[0]`（11） | b3 | 只画“地面类”（天空、草、水、花）的大底色，铺满不留缝 |
| 1 中 | `Q.layers[1]`（≈5.8） | b2 | 主体 |
| 2 细 | `Q.layers[2]`（≈3.1） | b1 | 细节 |
| 3 细节 | `Q.detail`（≈2.3） | b1 | 只在梯度大的地方以概率出现。天空跳过；亮度跳变过大的跳过，防止出现孤立杂点 |

- 非地面类（树、房、帆、人）在 li<2 时也从 b1 取色，以保证物体边缘清晰。
- 颜色只做很小的抖动：亮度 ±3.5%，加性 ±1.25%。**加大抖动会立刻变脏**。
- **方向规则**：
  - WATER 强制水平（±0.1 rad）。否则会出现“碎刀片”。
  - 相干度高时沿结构方向。
  - 草偏竖直，帆竖直。
  - 天空近水平。
- **尺寸**：长轴为网格间距的 1.0–2.2 倍，短轴 0.42–0.85 倍。水面短轴 ×0.72，粗层天空长轴 ×1.25。

### 4.3 草地里的花：先去红，再点花

如果粗层和中层直接从 b2/b3 取色，草里的小红花会和绿色混成一片粉橙色的雾。这是罂粟场景最初“糊、脏”的主要原因。做法如下：

- 用 `blurMasked()` 只对“纯草”像素（GRASS 且 `r <= g*1.08`）做模糊，得到 `g2`/`g3`，给草和花的粗层、中层取色。
- 红花只在细层（li≥2）出现：圆形色点（`mn ≥ 0.62*maj`），深度乘 0.996，保证压在草上面。
- 同理，任何“小而鲜艳的点状物”（花、光斑）都应该这样分离处理。

### 4.4 人物背后补底、特写细层

- **补底**：粗层遇到地平线以下的 FIGURE 像素时，在该像素对应的**地面深度**补一笔草（`g3` 取色，hot=0）。否则镜头前推或聚焦时，人物身后会露出空洞，看到背景色块。
- 物体的边缘（例如阳伞）必须完整地划进 FIGURE，否则边缘像素会被放到远处的地面深度，特写时“飘”在人物后面。
- **特写细层**：第 5 层（`fine`），间距为 `Q.detail*0.62`，直接用原图 `rgb` 取色，只覆盖人物和热点物体（75% 概率）。
- **光晕上限**：每个热点的 HALO 数量约为 700（`haloP = min(0.16, 700/n)`）。大面积热点不能按固定 16% 复制光晕，否则整片区域会蒙上一层雾。

### 4.5 关键：分层深度错开（解决“糊”）

```js
depth = depMap[i] * (1 + 0.014 * (3 - li));   // 粗层更远
```

排序只按视深，所以粗层必须在细层后面，否则大底色会盖住细笔触，画面一片糊。**这一行不能删，系数也不要小于 0.01。**

转场起点 `cpos` 是画布平面上的同一条视线，`sc` 也按层错开 0.4%。

### 4.6 转场延迟

`delay = 距画面中心的半径 * 0.62 + 随机 * 0.38`。中心先“活”，向外扩散。

## 5. 第 ④⑤ 步：调色板采样与全景扩展

### 5.1 调色板（只从原画采样，不允许凭空造色）

- **地面色**：按对数深度分 28 箱（`groundBins`）。远处取远处的颜色，近处取近处的颜色。
  - 草：只收 `g >= r*0.97` 的像素。否则罂粟的红会把草地染成粉米色。
- **水色 `pal.water`**：只收偏蓝的像素（`b > r*1.04 && b >= g*0.97`）。不加这个过滤，扩展水面会变成土黄或橄榄色。
- **天空**：按仰角分 18 箱，去掉最暗的 12% 和最亮的 1.5%。
  - 水景还要过滤掉偏暖或偏暗的天空像素（这些往往是被误分类的树梢或房顶）。
  - 派生出 `horizCol`（地平线色）、`clearCol`（最蓝的 12%）、`cloudHi`、`cloudLo`。
- **物体色**：`pal.tree/stat/sail/flower` 按亮度排序，用 `pickQ(arr, q)` 按分位取色，以控制明暗。

### 5.2 扩展内容（`ext.kind`）

| 内容 | 要点 |
|---|---|
| 地面 `field` | 环形分布 `ring`，近处密、远处稀；草浪笔触竖向、带 flex；花点稀疏地点缀 |
| 水面 `water` | 水平短笔，颜色为 `pal.water` 加上按掠射角混入的天空反射；着色器中扩展水面的短轴乘以 `clamp(graze*3.2+0.12, 0.16, 1)` 做透视压扁 |
| 倒影 `mirror()` | 物体点的镜像**投影到水面上**：`k = h/(h+yRel)*0.995`。短轴 ×k×4.2，长度 ×(2.2–3.6)×k，颜色更饱和、略暗。必须比水面笔触稍近，否则会被盖住看不见 |
| 树 `treeClump()` | 多个圆团（lobes）组成树冠，左上方受光；约 16% 是深色大底笔，用来补缝。不能做成“叠起来的球”。草地场景用 `sunLeaf`（树高光色与草亮色的混合）给受光面加暖色；近景圆树的笔触为 0.75 倍，数量相应增加 |
| 岸树 `bankTrees` | `[角度°, 距离, 高, 宽]`，用来接续画面右岸。负角度在右侧 |
| 远岸树林 | K=150 个团块，连续成带 |
| 房屋 `houses`、帆船 `boats` | `[角度°, 距离(, 高)]`，颜色取自 `pal.stat`/`pal.sail`。船体颜色为偏冷灰蓝 `[0.42,0.47,0.58]` |
| 草地细节（field） | fbm 大块明暗分区 + 按亮度排序的深度分箱分位取色；20% 贴地深色大底笔（位置远 1.5%）、草尖更亮、7% 近处深绿点缀；笔触近竖直并略向风向倾斜。**不要**逐笔随机取色，会变成没有结构的“白噪声草” |
| 罂粟/花点（field） | 圆形色点（短轴为长轴的 0.78–0.95 倍），只取原图中的纯红（`r>g*1.7`）并加饱和；距离 2.5–5 m 渐入、22–70 m 渐稀；着色器里花不按风拉伸 |
| 天空 | `horizCol → clearCol` 按仰角渐变，加上 fbm 噪声遮罩的水平云层带（`cloudLo → cloudHi`）。**不要用随机亮度分位逐笔取色**，那样天空会斑驳、发脏 |
| 大气透视 | `addExt` 对 HAZY 类（树、房、帆、草、花），按水平距离 30–150 m 向 `horizCol` 混色，最多混 50% |
| 粒子 | 光尘（MOTE，数量 `Q.motes`，尺寸上限 `0.006*vh`）、水面高光（GLINT）、花瓣（PETAL） |

所有扩展笔触都通过 `addExt()` 添加，并经过 `keep()` 过滤：落在原画矩形内部（并且超出 `EDGE_OUT` 带）的扩展笔触会被丢弃。从观看点看，画内永远只显示原画笔触。

## 6. 第 ⑥ 步：无缝画框（“一体”的关键）

三件事缺一不可：

1. **画内边缘溶解**：画内笔触在离边缘 `EDGE_IN=0.024` 的范围内按概率丢弃，最多丢 70%。
2. **扩展渗入**：扩展笔触在画内 `EDGE_OUT=0.05` 的带内按概率保留，最多保留 80%。两者交错，就没有硬边。
3. **`edgeBlend(w, col, family)`**：
   - 作用范围是画框外 `EDGE_M=0.26` 以内的扩展笔触。
   - 从最近的画框点沿向内方向搜索，找到**同族**像素（天空、水、陆地、帆四族）。
   - 找到后按 `(1-d/EDGE_M)^1.5 * 0.88` 把颜色插值过去。
   - 必须同族取色，否则天空会被拉成树色，水会被拉成岸色。

验收时，必须从正前方，以及左右各转 0.3–0.6 rad 截图检查四条边。看得出矩形轮廓（颜色台阶、密度台阶、笔触方向突变）就不合格。

## 6A. 统一笔触场（推荐做法，`src/unified.js`）

**为什么要改**：旧做法里，画内按像素网格采样原画，画外用另一套程序化规则（世界尺度的笔触、调色板颜色）。笔触尺寸、方向、颜色来源三者都在画框处突变，只能靠溶解和 `edgeBlend` 掩盖，用户一眼就能看出“画框里”和“画框外”。分层边界还是手画多边形，深度也互相矛盾（例如岸放在 31 m，但水岸线推出来只有 24 m）。

**核心思想**：整个球面只有一套规则，画框只是“哪里有原画像素可以直接取色”的区域。

### 6A.1 世界模型（画内由分割推出，画外同一曲面延续）

- 天穹（半径 `cam.sky`）、水面或地面（`y=-h`）、岸幕（离岸距离 `S(θ)`，高度来自岸的列剖面）、物体（船）。
- **接触深度**：每个非天空像素的深度 = 它脚下接触水面（地面）那一行的地面深度 `groundZ(v)`。
  - 船：配置 `contact`（船体吃水线的 v）。
  - 岸：水岸线 `wl(u)`。
  - 远岸：`farBank`。
  - 这样帆、岸、水岸线天然一致，换视角也不会漂。`cam.maxD` 要足够大（帆船是 450），否则远处的水会被压到同一深度。
- **水平线 `vH` 要量准**：帆船左侧远岸在 v≈0.545–0.556，水从 0.556 开始。以前把 0.556–0.61 的远水当成了天空，这就是“图层边界不准”的根源之一。
- 画外：`S(θ)` 在画框左右边缘等于画内边缘列的离岸距离，再平滑过渡到 `backDist`；岸高同理。

### 6A.2 一个方向采样器

- 绕画面中心视线 `front` 按环采样方向，间距 `α·k_layer·g(ψ)`。ψ 是偏离正前方的角度，`g = 1 + smooth(0.5, 2.6, ψ)`，最大到 2。
- 四层（粗 3.4 / 中 1.9 / 细 1.0 / 细节 0.72）用同一个采样器，所以画框处没有密度、尺寸跳变。层间仍按 `1+0.014*(3-li)` 错开深度。
- 每个方向 `resolve(d)` → 世界点 + 类别 + 取色的原画像素坐标 `(x, y)` + 是否镜像 `flip`。笔触方向取该像素的结构张量（镜像时取反）；水面强制水平。
- 画框内的方向 `ext=0`（转场从画布出发），画框外 `ext=1`（展开）。
- **预算**：数量约与 1/α² 成正比。帆船 `QUALITY.uniAlpha`：high 0.0059 / mid 0.006 / low 0.0071，分别约 29.7 / 28.8 / 20.5 万笔触。用户要求控制在 **20–30 万**。
- **薄带只收能放下的笔触**：远岸比粗、中层笔触还薄时，跳过这两层（`r.thin`），否则会出现漂浮的圆团。

### 6A.3 颜色永远来自原画

| 区域 | 取色方式 | 要点 |
|---|---|---|
| 画内 | 该像素本身；细层用 `b1`，粗/中层用**按族掩膜**的模糊（天空、水、岸、船四族互不渗色） | 填充要用 `inpaint()`（逐级加大半径的掩膜模糊），**不能**回退到不带掩膜的模糊，否则天空里会出现倒挂的岸 |
| 画外天空 | 从右边缘绕到背后再回到左边缘，用一条坐标做镜像延续；总长取奇数块，背后才能闭合；再叠加随方位和仰角变化的扭曲 | 只取离物体 ≥6px 的干净天空（`skyOK`）。莫奈在帆周围把天空画亮了，直接取会出现帆形鬼影。不用画布右缘没上色的褐条（`skyBad`、`skyRange`） |
| 画外水面 | 靠岸带：沿用岸列自己的倒影；开阔水面：取同距离那一行的无倒影水色（`waterOK`） | 没有干净像素的行在整行里随机取，不要把一个像素横向拖成条纹；签名区域（`waterBad`）不参与 |
| 画外岸 | 从右边缘起沿 `landPool` 列链往外走 | 标志性物体（红房子、大树）不放进列链，否则会紧挨着镜像重复；远处按距离降高、加雾、笔触放平 |
| 画外船 | 把画内的船按真实尺度重新摆放（`boatsOut: [方位°, 距离, 桅高, 源船]`），笔触密度与画内一致 | 倒影用 `mirror()`，尺寸要小（长 1.2–1.9 倍，短轴 1.4 倍），否则会变成水面上的大白椭圆 |

### 6A.4 分层边界：外框 + 颜色 + 掩膜

- 配置里的多边形只是**宽松外框**（`boats[].poly`、`land`），真正的边界由颜色决定。
- 先量颜色再定阈值（用 ffmpeg 把原图缩小后输出 rawvideo 逐点看）。帆船实测：天空的彩度 < 0.1，有时偏暖（b−r 低到 −0.09）；帆、船体、屋顶、树的彩度都 ≥ 0.17。所以：
  - `skyLike`：彩度 < 0.125，亮度 > 0.42，b > r − 0.11。
  - 帆附近用更严格的 `skyNearSail`（彩度 < 0.09，亮度 < 0.8，不偏暖），奶油色高光归帆。
  - 偏绿的像素归岸，不归船。远岸带里偏暗的像素不归船。
- 每个物体掩膜做闭运算并填**小**洞：船填到 4000px（帆面上蓝灰的阴影不能变成天空），岸只填 24px（树缝里的天空要保留）。
- 用 `node tools/segdump.mjs --scene 1 --out /tmp/seg` 输出 `cls.png`（类别叠加原图），以及 `sky.png`、`water.png`、`land.png` 三张填充图。边界和填充都要逐张看过。

### 6A.5 着色器

`uUnified=1` 时，所有水面笔触（包括画内）都按掠射角压扁短轴（下限 0.4），力度乘以转场进度 `settled`。这样展厅里看到的仍是原画，进入画境后水面才逐渐变得有透视感。

### 6A.6 纸片书式层次（视差 + 深度卡片）

只转头不移动眼睛时，深度看不出来，场景会显得“都在一个图层上”。做法分四部分：

- **眼睛平移**：`cam.parallax`（帆船 2.4 m）。`main.js` 的 `updateLook` 让眼睛跟随鼠标或演示光标横移，空闲时缓慢漂移。只有 `fMix > 0.82`（画框已经展开）时才生效，否则会破坏画框变形；特写时减到 0.45 倍。
- **岸的卡片**：画内岸按“高出水线的高度 dv”分层：岸边一条（dv < 0.035）在 1 倍；树一层在 ×1.35；房屋（暖色屋顶、浅色墙，先做颜色图再 4px 平滑，叫 `builtMap`）在 ×2.3；越高再往后退 0.15。画外岸用同样方法按 `fr` 分层。不能用 `CLS.TREE/STATIC` 区分，因为莫奈的橄榄绿树几乎都被判成 STATIC。
- **补底**：前一层移开后会露出后面。画内近岸（深度 < 150 m）的 li 0/1 笔触在靠近天空处补一笔天空或远水（`behind`），其余补一笔 ×2.6 深度的岸色。画外岸脊（`fr > 0.45`）补天空（`skyAt`）。船的补底跟以前一样。
- **倒影跟着眼睛走**：倒影笔触 `flex = -m`，其中 `world*m` 是物体在水下的镜像点。着色器求“镜像点到眼睛的连线”与水面的交点，只把相对参考眼的偏移加上去。画内笔触的参考眼是 `uEye0`（推进后的位置）；画外笔触的参考眼是原点，因为它们本来就是按原点摆放的。否则眼睛一动，倒影就成了斜线。

验收：`node tools/shot.mjs --scene 1 --yaws 0,1.3 --look "-1,0;1,0"` 左右眼对比；`node tools/sweep.mjs /tmp/sweep 0.05` 出连续帧做视频。量一下各层位移：岸边 > 树 > 房屋 > 远岸 ≈ 天空。

### 6A.7 验收时必须看的镜头

正前（`--yaws 0`）、左右各 0.6、侧面 ±1.6、背后 3.1、局部放大（`--fov 30`）、热点特写（`--focus`）、转场中途（`--mid 1.2/2.2/3.4`）、左右眼（`--look "-1,0;1,0"`），还有 `segdump`。尤其要找这几类问题：帆形鬼影、镜像轴、重复地标、漂浮的小块、水面大椭圆、倒影被拉成斜线、层与层之间露空，以及低头看脚下（`--pitch -0.9`）时的扇形和同心圈。脚下所有方位角都汇聚在一点，所以按方位角取色、或者笔触沿视线横向摆放，都会在那里形成放射纹。处理办法：俯角大于约 17° 之后，水面改为按地面坐标取色，笔触平铺在水面上、方向随机。

## 7. 第 ⑦ 步：数据打包与排序（`splats.js` / `sort.js`）

- 每个笔触占 5 个 texel（RGBA32F）：
  - A = 世界坐标 + seed
  - B = 画布坐标（转场起点）+ cls
  - C = 长轴向量 + 短轴长度
  - D = 颜色 + alpha
  - E = hot、flex、delay、ext 标志
- 排序：先视锥剔除，再按对数视深做 16 位计数排序，从后往前画。实时模式在 Worker 里排序；录制和截图模式下同步排序（`syncSort`），保证结果确定。
- 数量预算（mid 档）：罂粟约 29.2 万，帆船约 30.3 万。超过 35 万时，弱显卡会明显卡顿。

## 8. 第 ⑧ 步：调色 `grade`（解决“暗/土黄”）

着色器 `grade()`（`splats.js`）的处理顺序：gamma → 曝光 × 白平衡 → **去泥 `cleanMud`** → 饱和度 → lift（向柔肩色调曲线 `(1-e^{-1.8g})/(1-e^{-1.8})` 混合，提亮暗部和中间调，同时压住高光）→ 对比度。最终输出与原色按 `uGrade` 混合。

| 参数 | 作用 | 罂粟 | 帆船 |
|---|---|---|---|
| `gamma` | 小于 1 提亮中间调 | 0.96 | 0.9 |
| `expo` | 整体曝光 | 1.04 | 1.1 |
| `wb` | RGB 白平衡，蓝大于红就偏冷 | [0.97,1,1.05] | [0.94,1,1.1] |
| `clean` | 去泥强度（见下） | 0.8 | 1 |
| `sat` | 饱和度 | 1.2 | 1.18 |
| `lift` | 柔肩曲线混合比例，越大越通透、越不脏 | 0.1 | 0.34 |
| `contrast` | 对比度 | 1.12 | 1.06 |

- **去泥 `cleanMud`**：全局的饱和度和白平衡会把暗中调的土黄、褐绿一起推高，变得更脏。所以先只挑这类颜色处理：偏黄（`(r+g)/2-b` 大）且不亮（亮度 < 0.55~0.85）。偏绿的（橄榄、褐绿）减红加蓝，变成清新的冷绿；偏红的（土黄、褐）整体提亮、往米金色走，不能往粉色走，否则屋顶会变成三文鱼色。暖灰（彩度低又偏黄）往蓝灰推，暗部整体加一点冷蓝，和天空、河水统一。JS 里的 `gradeColor` 有同样的实现，背景天穹也一起调。

- 原画扫描件普遍偏暗偏黄（老化的光油）。**沉浸态必须做偏冷、提亮的调色**，但不要让高光溢出成死白。
- `uGrade` 在转场中补间：进入时延迟 1.1 s，用 3.4 s 从 0 到 1；离开时延迟 0.6 s，用 3.0 s 回到 0。因此在展厅里看到的仍是原画色调，转场起点与 DOM 原画对齐。
- 背景天穹在 JS 里用 `gradeColor()` 预先调色。修改 grade 后两边会自动一致。
- **不要**在 `#gl` 上加 CSS filter 做调色（以前加过，会让转场首帧对不上，已删除）。暗角也要很轻：`rgba(12,16,24,0.3)` 从 62% 开始。颗粒 opacity 为 0.03。

## 9. 第 ⑨ 步：笔触形状（解决“糊/脏”，片元着色器）

- 笔触是一个各向异性椭圆，带不规则轮廓（边缘按 seed 起伏），边缘过渡宽度为 `rim = clamp(1.4/vPx, 0.12, 0.6)`。
  - `vPx` 是笔触的屏幕像素尺寸。笔触越大，边缘越锐利。
- 天空用 `vPx*0.3` 计算 rim，边缘更柔，避免天空出现一颗颗硬点。
- 笔触内部有极弱的“刷痕”（streak）明暗，幅度只有几个百分点。**加大就会脏**。天空关闭刷痕（`vBr=0`），否则大量细长的天空笔触会叠出细密的划痕条纹。扩展天空的笔触长度为 R×0.026–0.05，不要再小。
- 风只让草（cls 1）弯折、拉长、提亮浪尖（提亮幅度很小：`col*1.14+0.05`，混合 0.6）。花只轻微转动，否则圆形花点会被拉成“火苗”或“纸片”。
- 最小屏幕尺寸为 0.9 px，防止远处闪烁。光尘有尺寸上限，防止镜头前出现大白团。

## 10. 第 ⑩ 步：转场、风与热点（`main.js`）

- **离轴视锥对齐**：`galleryFrustum` 根据 DOM 中画作 `<img>` 的屏幕矩形计算 `makePerspective(l,r,t,b)`，使 3D 画布平面与 DOM 图片逐像素重合。
  - 改展厅布局（CSS）后要检查：转场第一帧不能跳。
- **转场**：每个笔触在 `cpos`（画布平面）和 `world` 之间按 `delay` 错开插值。相机同时前推 `dolly`，视场展开。
  - 期间 `uGrade` 渐变，HUD 淡入。
- **单一时钟**：所有动画都走 `clock` + `tween()`。录制时由 `window.__step(dt, draw)` 驱动。
- **风**：
  - 顶点着色器按 `cls`、`flex`、`wind` 做位移（草浪、树摇、帆鼓、水波）。
  - HUD 滑块调节风力。
  - 实时风声由 `audio.js` 根据 `S.windLevel` 生成。
- **热点**：
  - 光晕笔触呼吸发光，点击后相机朝热点中心拉近 `zoom` 倍，并弹出卡片。
  - 其余区域按**径向**柔和压暗：`uFocusPos/uFocusR`，从 0.9R 到 2.6R 做 smoothstep，去饱和 0.28，压暗 0.2。
  - **不要**按热点 id 做矩形压暗，会出现矩形亮块。
- **懒加载**：启动时只生成第一幅画，切换画作时再生成其他画，避免低端机卡死。
- **HUD 点击穿透**：`#hud` 只有在 `.on`（沉浸态）时才接收指针事件。否则透明的 HUD 会挡住展厅的切换按钮。

## 13. 注意点与已踩过的坑

| 现象 | 根因 | 正确做法 |
|---|---|---|
| 画面整体糊 | 粗底色和细笔触在同一深度，排序后粗的盖住细的 | 分层深度错开（4.5），并使用硬边笔触（第 9 节） |
| 草里的花糊成粉橙色雾 | 粗层、中层模糊取色，红绿混在一起；大面积热点的光晕太多 | 去红的底色（4.3）、细层圆点、光晕上限 |
| 特写时人物背后有色块或空洞 | 人物像素位置没有地面底层；物体边缘被分到远处的地面 | 补底（4.4），物体边缘划进 FIGURE |
| 花点像火苗或纸片 | 花随风拉伸，长宽比太大 | 圆形色点，花不拉伸 |
| 地平线上出现一条红色虚线 | 远处花点太密 | 按距离渐稀 |
| 扩展天空有细密划痕 | 天空笔触太小，刷痕形成条纹 | 加大笔触，天空 `vBr=0` |
| 画面脏、斑驳 | 颜色抖动太大；天空逐笔随机取分位色；细节层出现孤立亮暗点 | 抖动 ≤3.5%；天空用渐变加云层遮罩；细节层过滤亮度跳变 |
| 偏暗、偏土黄 | 原画扫描件偏黄；水色取到了倒影中的绿和棕 | 冷调提亮的 grade；水色只取偏蓝像素 |
| 看得出画框 | 画内外笔触密度、颜色、方向不连续 | 改用统一笔触场（6A）：同一采样器、同一世界模型、颜色都取自原画 |
| 扩展天空里有帆形鬼影 | 莫奈在帆周围把天空画亮了；或者填充回退到了不带掩膜的模糊 | 只取离物体 ≥6px 的干净天空；填充用逐级掩膜 `inpaint()` |
| 侧面天空有对称的“漏斗”纹 | 镜像延续的轴正好落在画布边缘的坏像素上 | `skyRange` 避开坏边，并加随仰角变化的扭曲 |
| 地标紧挨着重复 | 岸的列链里包含红房子 | 列链只放普通灌木和树的列 |
| 远处岸像漂浮的圆团或叶片 | 粗笔触比岸还高 | 薄带跳过粗/中层，远岸不要拆成零碎小块 |
| 帆面有洞、透出天空 | 帆的蓝灰阴影被判成了天空 | 帆附近用严格的天空判据，掩膜做闭运算并填洞 |
| 水面“碎刀片” | 水面笔触沿结构张量方向画成了竖向 | WATER 强制水平 |
| 倒影看不见 | 倒影在水面下方，被更近的水面笔触覆盖 | 投影到水面并稍微靠近相机，同时加宽加长、增加饱和度 |
| 草地发粉 | 草的颜色箱混进了罂粟的红 | 草只收 `g >= r*0.97` 的像素 |
| 树像叠起来的球 | 树冠用的是规则的球体分布 | 不规则圆团加深色底笔 |
| 镜头前出现白色大团 | 光尘尺寸没有上限 | 上限 `0.006*vh` |
| 聚焦时出现矩形亮块、四周发灰 | 按 id 压暗，热点区域是矩形 | 径向柔和压暗，并降低压暗幅度 |
| 转场首帧跳 | DOM 矩形与视锥没有对齐，或 `#gl` 上加了 CSS filter | `galleryFrustum` 对齐，并且不加 filter |
| 展厅切换画作没反应 | 透明的 HUD 挡住了点击 | 只有 `#hud.on` 时才接收指针事件 |
| 截图或录制卡在展厅 | 同一次 evaluate 中同步循环调用 `__step`，Promise 链没有推进；或者 capture 自动跑了 demo | 每步之间让出事件循环；加 `&nodemo` |
| CDN 打开时报 tainted | 图片跨域 | 设置 `crossOrigin='anonymous'` |
| `file://` 打不开 | ES Module 和 getImageData 的限制 | 必须用 http 服务（start.bat / start.command） |
| 低端机卡死 | 一次生成两幅画，并且默认 high 档 | 懒加载，默认 mid 档，提供 `?q=low` |
| palette 代码报 TDZ 错误 | 在 `ext` 定义之前就引用了它 | 使用 `scene.ext.kind` |

其他约定：

- 随机数一律用 `makeRng(seed)`，**不要**用 `Math.random`，以保证每次生成的场景完全一致（录制可以复现）。
- 原生 ES Module，无构建，Three.js r170 从 `vendor/` 通过 import map 引入。
- 注释很少，只写代码本身表达不了的约束。

## 14. 新增一幅画的操作清单

1. 把画放进 `assets/paintings/<id>.jpg`。
2. 在 `scenes.js` 新建一个配置对象，并加入 `SCENES`：
   - `id`、`image`、`info`
   - `cam`（对照原画量出 `vH`）
   - `grade`（可以先抄帆船的参数）
   - `wind`、`hotspots`
3. 写 `unified` 配置（推荐，见 6A）：水岸线或地面线 `water`、远岸 `farBank`、物体外框和接触行 `boats`、岸外框 `land`、列链 `landPool/farPool`、热点函数 `hot`、画外物体 `boatsOut`、坏区 `skyBad/waterBad/skyRange`。先用 `segdump` 把分层看对，再截图。
4. 如果是新地貌（例如花田、雪地），把“水面”换成对应的地面，物体的 `contact` 改为它脚下的地面行，其余流程不变。旧的 `classify` + `ext` 只在维护罂粟场景时参考。
5. 运行 `python3 tools/fonts.py` 更新字体子集。
6. 依次截图调整：正前（与原画对齐，无边框）→ 左右 → 背后 → 抬头 → 热点。
7. 在 `demo.js` 中加入演示段落，用 `--dry` 把总时长控制在约 2 分钟。
8. 在三个档位（high/mid/low）下检查笔触数量和帧率。
9. 按第 15 节逐项验收后再提交。

## 15. 完成要求（验收清单）

### 画面

- [ ] 正前方截图与原画构图一致，不变形、不缺块。
- [ ] 正前方左右各转 0.3–0.6 rad，四条边都看不出矩形边界（无颜色台阶、无密度台阶、笔触方向无突变）。
- [ ] 整体明亮偏冷，没有土黄或橄榄色；天空通透，水面偏蓝并带天光。
- [ ] 笔触边缘清晰，在 1080p 下 100% 查看不糊；没有斑驳杂点、灰色碎笔、镜头前大团。
- [ ] 背后和侧面的扩展内容合理（地平线连续，树、房、船分布自然，有大气透视）。
- [ ] 水景：倒影清晰可见，与物体上下对应；水面有掠射压扁和高光闪烁。
- [ ] 天空：渐变加云层带，没有深色短笔或斑点。

### 交互与动效

- [ ] 展厅可以切换所有画作；每幅画都能进入，也能离开。
- [ ] 转场首帧与展厅原画像素级对齐，没有跳变；调色在转场中平滑过渡。
- [ ] 风力滑块有效，草、树、帆、水的动效符合各自类别。
- [ ] 每个热点都能点击拉近，卡片文案正确，聚焦时只做径向柔和压暗。

### 性能与兼容

- [ ] 三个档位的总笔触数都在 20–30 万之间（控制台会打印 `[monet] unified layers ... total N`）；`?q=low` 可以在核显上流畅运行。
